# OMS Playwright Automation

This repository contains the Playwright test automation suite for the Order Management System (OMS) and associated Storefront integrations.

## Architecture: Atomic Data Pooling

This automation framework features a highly robust **Atomic Data Pooling Architecture** designed to make OMS flows 100% independent and capable of massive parallel execution without data collisions.

### Project Structure
```text
├── config/                 # Dynamic client environment & auth configuration loader
├── data/                   # Output directory for Shopify seeded data (e.g. pooledOrders.csv)
├── data_seeding/           # Scripts to hit Shopify API and spin up the Local Test Data Server
├── fixtures/               # Playwright fixtures to automatically authenticate and pop pooled data
├── pages/                  # Page Object Models (POM) holding UI interaction logic and locators
├── tests/                  # Playwright Spec files orchestrating the Page Objects
├── utils/                  # Reusable utilities (auth state management, etc.)
├── global-setup.js         # Playwright hook to initialize the Test Data Server before tests start
├── global-teardown.js      # Playwright hook to shut down the Data Server after tests finish
└── playwright.config.js    # Core Playwright configuration (Parallelism, Retries, Reporters)
```

### Configuration Loading Hierarchy
The framework dynamically maps environments through `config/clients.js`. It loads configuration in a 3-tier priority list:
1. **Global CLI Overrides (Highest Priority):** Passing `CLIENT=...`, `URL=...`, `USERNAME=...` directly in your terminal command.
2. **Client-Specific Prefixed Environment Variables:** Setting variables like `ADOC_PA_UAT_URL` in your `.env`.
3. **Structured JSON (Fallback):** Parsing the comprehensive `CLIENTS` JSON object in your `.env` file (See `.env.example`).

### Graceful UI Fallback & Bypassing the Data Pooler

The framework is designed to automatically bypass the Shopify data pooler and safely fallback to searching the UI for existing organic orders in three specific scenarios:

1. **Explicit Bypass via CLI:** If you pass `NUM_ORDERS=0` in your command (e.g., `CLIENT=mephisto-uat NUM_ORDERS=0 npx playwright test ...`), the pooler instantly exits and produces an empty data pool. This allows you to skip the 6-minute webhook sync wait time and forces the test to use existing organic data.
2. **Exhausting the Pool:** If you generate 2 orders by default (`NUM_ORDERS` defaults to `1` if omitted) but run 3 tests in parallel, the third test will detect that the pool is empty and gracefully fallback to the UI search rather than failing.
3. **Missing Credentials or API Errors:** If Shopify is down or the client is missing credentials in `config/clients.js`, the pooler fails safely and allows the tests to proceed using organic UI data.

> [!IMPORTANT]
> **Safety Mechanism:** When tests fallback to the UI search, they are strictly configured to only pick up orders that match the random first names generated by our automation script (e.g., Emma, Liam, Olivia). It will completely ignore orders manually created by real human QA testers, ensuring other people's workflows are never hampered! Additionally, UI-heavy flows like `createsalesreturn` actively count available matching records and interact with a **randomized index** rather than strictly picking the first row, heavily reducing the likelihood of hitting exhausted data.

## Getting Started

### Prerequisites

- Node.js (v18+)
- NPM
- Playwright

### Installation

1. Install dependencies:
   ```bash
   npm install
   ```
2. Install Playwright browsers:
   ```bash
   npx playwright install
   ```
3. Set up the environment variables:
   Copy `.env.example` to `.env` and fill in the necessary credentials. The `CLIENTS` variable contains a JSON string with specific configuration per brand/region.

**CRITICAL PREREQUISITE FOR AUTOMATION:**
To generate valid real orders via the Shopify API, you **must** supply a valid `productVariantGid` for each client in your `.env` file. If the Variant ID is missing or invalid, Shopify creates a "Custom Line Item", which HotWax OMS will ignore and fail to sync.

## Execution Commands

The framework supports a wide variety of execution combinations, allowing you to seed data dynamically and run tests across specific clients and browsers.

### Step 1: Seed the Data Pool (Recommended)
Before running the tests, generate fresh orders to guarantee test independence and speed. The seeding script hits the Shopify API and polls the HotWax OMS to ensure the webhooks have successfully synced the data.

**Seed 1 order for the default client (krewe-uat):**
```bash
npm run test:oms:seed
```

**Seed multiple orders for a specific client (e.g., 6 orders for adoc-sv-uat):**
```bash
CLIENT=adoc-sv-uat NUM_ORDERS=6 npm run test:oms:seed
```

### Step 2: Execute Tests

**1. Run the Entire Suite (All Clients & Flows)**
```bash
npx playwright test
```

**2. Run a Specific Client (e.g., Krewe on Chromium)**
```bash
CLIENT=krewe-uat npx playwright test --project="krewe-uat - Chromium"
```

**3. Run a Specific Flow (Specific File)**
```bash
npx playwright test tests/Order_Types/Sales_Order/cancelorder.spec.js
```

**4. Run with UI Visible (Headed Mode)**
```bash
CLIENT=adoc-sv-uat npx playwright test --project="adoc-sv-uat - Chromium" --headed
```

**5. Run a Specific Browser (e.g., Firefox)**
```bash
CLIENT=thirdlove-uat npx playwright test --project="thirdlove-uat - Firefox"
```

**6. Run Tests by Tag / Keyword (e.g., specific test title)**
```bash
npx playwright test --grep "Release Sales Order"
```

**7. Run with Increased Parallelism (Workers)**
```bash
npx playwright test --workers=4
```

**8. Run in Debug Mode (Inspector)**
```bash
npx playwright test --debug
# or use the npm shorthand:
npm run test:debug
```

**9. Open Playwright UI Mode (Interactive Visual Runner)**
```bash
npm run test:ui
```

**10. Run ONLY Sales Order Tests**
```bash
npm run test:oms
```

---

### Step 3: Utility Commands

**Clear Saved Authentication Sessions**
If you change passwords or need to force a fresh login across all clients, run this command to clear the cached `.auth` state:
```bash
npm run auth:clear
```

- **API Errors:** `AuthExpiry.spec.js` (401/403), `CancelOrder.spec.js` (500 Server Errors)
